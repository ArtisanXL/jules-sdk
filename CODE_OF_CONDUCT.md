# Code of Conduct

## Our Commitment

The Jules-SDK community is committed to providing a welcoming, inclusive and respectful environment for everyone.

We value constructive collaboration, thoughtful discussion and professional conduct. Contributors, maintainers and community members are expected to treat one another with respect regardless of experience level, background or role within the project.

Our goal is to foster an environment where people feel comfortable contributing ideas, asking questions and improving the project together.

---

## Our Standards

Examples of behavior that contribute to a positive environment include:

* Being respectful and considerate in all interactions.
* Providing constructive and actionable feedback.
* Welcoming differing viewpoints and experiences.
* Assuming good faith during technical discussions.
* Accepting constructive criticism gracefully.
* Helping others learn and grow within the community.
* Prioritizing collaboration over confrontation.
* Maintaining professionalism in public and private communications.

Examples of unacceptable behavior include:

* Harassment or discriminatory language of any kind.
* Personal attacks, insults or intimidation.
* Trolling, inflammatory comments or deliberately disruptive behavior.
* Publishing private information without explicit permission.
* Repeatedly derailing discussions or pull requests.
* Deliberately misleading contributors or reviewers.
* Abusive or hostile conduct directed at community members.
* Any conduct that could reasonably be considered inappropriate in a professional and collaborative environment.

---

## Scope

This Code of Conduct applies to all project spaces, including but not limited to:

* GitHub Issues
* Pull Requests
* Discussions
* Documentation contributions
* Project-related communications
* Community events organized by the project

It also applies when an individual is officially representing the Jules-SDK project in public spaces.

---

## Community Expectations

We encourage contributors to:

* Ask questions respectfully.
* Explain technical decisions clearly.
* Focus discussions on ideas rather than individuals.
* Welcome constructive disagreement.
* Provide helpful reviews and suggestions.
* Keep conversations productive and inclusive.

Disagreements are a natural part of collaborative software development. Technical disagreements should remain professional, respectful and focused on improving the project.

---

## Open Source Philosophy

Jules-SDK embraces the following principles:

* Respectful collaboration
* Technical excellence
* Transparency
* Long-term maintainability
* Continuous learning
* Inclusive participation

Contributors are encouraged to prioritize:

* Readability
* Maintainability
* Documentation
* Testing
* Developer experience
* Community well-being

---

## Enforcement Responsibilities

Project maintainers are responsible for:

* Clarifying and enforcing the Code of Conduct.
* Reviewing reports fairly and consistently.
* Taking appropriate action when violations occur.
* Maintaining a respectful and collaborative environment.

Maintainers may remove, edit or reject comments, commits, pull requests, issues or other contributions that violate this Code of Conduct.

---

## Reporting Violations

If you experience or witness unacceptable behavior, please report it privately to the project maintainers.

Reports should include:

* A description of the incident.
* Relevant dates and times, when available.
* Links or references to the relevant discussions or content.
* Any additional context that may assist in understanding the situation.

All reports will be reviewed respectfully and handled as confidentially as reasonably possible.

---

## Enforcement Guidelines

Responses to violations may include, but are not limited to:

### 1. Correction

For minor issues, maintainers may provide guidance regarding appropriate behavior and request corrective action.

### 2. Warning

Repeated or more serious violations may result in an official warning from the maintainers.

### 3. Temporary Restrictions

Contributors who repeatedly violate this Code of Conduct may receive temporary restrictions from participating in project spaces.

### 4. Permanent Restrictions

Severe or repeated violations may result in permanent removal from participation within the project's community spaces.

Maintainers will exercise reasonable judgment when determining appropriate actions.

---

## Maintaining Constructive Discussions

When participating in technical discussions:

Prefer:

```text
"This approach may introduce unnecessary allocations."

"I believe this implementation could be simplified."

"Could we consider an alternative API design?"
```

Avoid:

```text
"This is terrible."

"You clearly don't understand Rust."

"This implementation is useless."
```

Constructive feedback helps improve both the project and the contributor experience.

---

## Code Review Expectations

All contributors are encouraged to:

* Review code respectfully.
* Explain requested changes clearly.
* Focus on technical considerations.
* Avoid dismissive or hostile language.
* Recognize the effort invested in contributions.

Code reviews should aim to improve the project rather than discourage participation.

---

## Artificial Intelligence Contributions

Contributions created or assisted by AI tools are welcome provided that:

* Contributors remain responsible for the submitted changes.
* Generated code is reviewed before submission.
* Documentation and tests are included when appropriate.
* Contributions comply with the project's quality standards.

AI-assisted contributions are held to the same standards as all other submissions.
